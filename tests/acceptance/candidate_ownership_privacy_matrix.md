## Result and limitations

- **Resource-specific ownership/privacy coverage:** Each listed surface has focused integration or security test evidence in the backend suite.
- **CI evidence:** The code/test baseline above passed the configured CircleCI job, which applies migrations, checks ORM/schema parity, and runs unit plus PostgreSQL integration tests.
- **No existence leak:** Tests use resource-specific denial behavior where IDs are addressable. Profile endpoints are user-resolved rather than accepting another candidate's profile ID; tests verify a second principal sees their own isolated profile instead.
- **Remaining limitation:** This is a traceability matrix over existing tests, not a single generated cross-resource attack harness. A consolidated API-wide test suite and target-environment authorization checks remain useful follow-up hardening, but the listed backend test paths cover the canonical resource set.
- **Runtime boundary:** Firebase provider operation, SMTP, OCR/R2/Drive, live source access and deployed worker/recovery behavior remain NOT VERIFIED without authorized staging evidence. See `docs/operations/candidate-runtime-smoke-checklist.md`.
